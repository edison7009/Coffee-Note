# Note Agent「省钱 Note」临时产品备忘录

> 状态：临时记录，后续补充为正式产品定位、官网文案和定价说明。
>
> 这份文档的目的只有一个：不要忘记 TierNote 的核心爆点不是“又一个
> coding agent”，而是一个让普通用户用更便宜模型、更少 token 管好自己笔记的
> Note Agent。

## 核心定位

**TierNote = 省钱的 Note Agent。**

它不是要求用户购买 Claude、GPT 或 Opus 的 coding 工具，也不是把用户推向更
昂贵的模型。它应该让用户选择自己负担得起的模型，优先使用本地笔记和个人资料，
用尽可能少的调用完成整理、检索、压缩、更新和治理。

可以暂时使用这句内部定位：

> 让每一个 token，产出至少两倍价值。

这里的“至少两倍”是产品目标和价值主张，不是未经基准测试的成本保证。正式对外
发布前，需要用真实任务、模型价格、token 用量和调用次数建立可复现的对比数据。

## 我们解决的三个痛点

1. **我不想用 Claude 或 GPT 这类 coding 负责工具管理我的笔记。**
   我只想要一个专门理解、整理和治理笔记的工具。
2. **我不想被 Opus 或 GPT 系列模型绑定。**
   我希望使用便宜、够用、可替换的模型，而不是为了管理笔记支付 coding agent 的
   高价。
3. **我只想用最便宜的模型和最省 token 的工具。**
   TierNote 应该帮我把资料治理好，而不是用更多上下文、更多轮次和更长输出制造
   更高账单。

## 当前已经具备的省钱机制

- **Economy mode 默认开启**：限制常规回答的输出长度和工具轮数；需要深度综合时
  才切换 Full mode。
- **DeepSeek 兼容与缓存友好**：保持稳定的系统提示和请求结构，尽量复用供应商
  前缀缓存，并在界面展示 cache hit 和 token 使用情况。
- **高命中率记忆路由**：先取用户当前打开的笔记和“我的资料”，再按问题选择少量
  相关记忆，不把整本资料库重复塞给模型。
- **Library Graph 检索**：在本地 Markdown 库内按标题、路径、标题层级、正文和
  Markdown 链接扩展检索；不依赖 embedding API、向量数据库或额外索引 token。
- **短输出、少调用、自动压缩**：优先返回可执行的短答案；重复工具调用会被阻止，
  过长上下文会按阶段裁剪、压缩和保留近期内容。
- **本地优先**：个人资料、笔记和记忆索引留在本机；只有用户发起 AI 请求时才发送
  必要上下文，减少无意义的数据上传和重复处理。
- **模型可替换**：协议、地址、模型和密钥分开保存，不把用户锁定在某一家昂贵模型
  或某一种 coding workflow。
- **成本可见**：对话中展示 token、请求次数、缓存命中率和可用时的成本估算，让
  用户知道一次整理到底花了多少。

## 省钱的工作原则

1. 先本地检索，后请求模型；先小上下文，后按需扩展。
2. 先做确定性的文件操作和结构化处理，再把真正需要判断的部分交给模型。
3. 一个清晰工具调用胜过多轮试探；重复调用、重复全文和无意义解释都要削减。
4. 记忆与资料分层：确认过的信息写入可见 Markdown，索引可重建，不为恢复能力长期
   支付正文 token。
5. 便宜模型是默认可行路径；只有任务确实需要深度综合时，才建议升级模型或模式。

## 后续必须补充的证据

- DeepSeek 与其他低价模型的真实 token、缓存命中率和调用次数基线。
- Economy mode 与 Full mode 在常见笔记任务上的成本/质量对照。
- “至少两倍价值”对应的具体衡量方式，例如：一次调用完成的有效笔记字段数、
  重复调用减少率、每千 token 完成的治理任务数。
- 用户可理解的价格档位和模型推荐，不制造“贵模型一定更好”的暗示。
- 失败、重试、超时和模型能力不足时的降级策略，确保省钱不会变成卡住或悄悄丢内容。

## 暂不做的事

- 不把 TierNote 包装成 coding agent 的简化版。
- 不强制用户购买 Claude、GPT 或 Opus。
- 不用“更长上下文”“更强模型”作为唯一产品竞争力。
- 不在没有数据的情况下承诺固定百分比的省钱效果。

## 一句话方向

**不是让 AI 写更多，而是让更便宜的 AI 用更少的 token，把你的笔记治理得更好。**
